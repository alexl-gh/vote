# Анонімізована система взаємооцінювання (Proof-of-Concept)

Гібридний веб-додаток для проведення анонімного оцінювання всередині академічних груп. Архітектура забезпечує деперсонізацію голосів, можливість збереження проміжного прогресу та підтримку крос-платформеного доступу (смартфони, ПК) без необхідності реєстрації користувачів.


1. Архітектура Рішення
Фронтенд (Клієнтська частина): Односторінковий додаток (SPA), написаний на чистому HTML/CSS/JavaScript. Забезпечує адаптивний мобільний інтерфейс, маскування введення токенів, рендеринг критеріїв та повзунків. Розгорнутий на хмарному хостингу Netlify (PoC-адреса: https://funny-babka-59ec7e.netlify.app/).

Бекенд (API): REST API, реалізований за допомогою Google Apps Script (GAS). Приймає POST-запити від фронтенду, обробляє логіку перевірки токенів та управляє станами збереження.

База даних: Google Sheets (Сховище), яке виконує роль "сліпого" бекенду. Розділено на три ізольовані таблиці:

Tokens — словник доступу.

Criteria — параметри оцінювання.

Votes — результати та збережені чернетки (драфти).

2. Workflow Адміністратора (Підготовка системи)
Генерація доступів: За допомогою Python-скрипта генерується унікальний набір 6-значних буквено-цифрових кодів (наприклад, ATW-8HX). Алфавіт токенів виключає символи, які легко сплутати (0, O, 1, l).

Заповнення БД: Згенеровані токени разом із деперсоніфікованими ідентифікаторами (наприклад, student1, teacher1) вносяться на аркуш Tokens у Google Sheets.

Налаштування критеріїв: На аркуші Criteria задаються параметри оцінювання (наприклад, "Командна робота", "Чесність") та їхні описи.

Деплой бекенду: Скрипт GAS розгортається як Web App з доступом "Усі (Anyone)", генеруючи унікальний URL для прийому даних.

Деплой фронтенду: Файл index.html із вшитим URL бекенду завантажується на хостинг.

Дистрибуція: Роздруковані токени лунають учасникам відповідно до списку групи.

3. Workflow Користувача (Студента/Викладача)
Авторизація: Користувач відкриває посилання веб-додатка і вводить свій 6-значний токен. Фронтенд автоматично форматує введення. При успішному вході система завантажує персоналізований інтерфейс (студент бачить бейдж "Самооцінка" напроти свого ідентифікатора) та відновлює попередній прогрес, якщо він був.

Оцінювання: На екрані з'являється поточний критерій. За допомогою інтерактивних повзунків користувач виставляє оцінки всім учасникам групи від 1 до 5 (за замовчуванням встановлено 3 бали).

Збереження прогресу: При переході до наступного критерію (кнопка "Далі"), клієнтський скрипт формує JSON-пакет і непомітно відправляє його на бекенд. Дані записуються зі статусом draft. Проміжні результати зберігаються на сервері — закриття браузера не призведе до втрати даних.

Завершення сесії: На останньому критерію натискання кнопки "Завершити голосування" переводить усі draft записи цього користувача у статус submitted. Інтерфейс блокується, зміна оцінок стає неможливою.

4. Особливості безпеки та анонімізації
Відсутність персональних даних: Жоден обмін даними між фронтендом та БД не містить реальних ПІБ — лише ідентифікатори типу student8. Зіставити результати з реальними людьми може лише адміністратор, який має фізичний журнал видачі токенів.

Захист від перебору: Короткі токени генеруються криптографічно випадково. На боці бекенду (Apps Script) імплементовано штучну затримку (throttling), що робить автоматичний підбір чужих токенів неефективним.

Ізоляція доступу: Користувачі не можуть переглядати таблиці Google Sheets. Взаємодія відбувається виключно через обмежений API-ендпоінт, який має право читати та писати дані лише в межах наданого токена.
